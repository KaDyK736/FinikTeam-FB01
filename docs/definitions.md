# DoR/DoD критерии и метрики — Faberlic AI Assistant (FB01)

## 1. Definition of Ready (DoR) для задач
Задача считается готовой к разработке, если:
- Есть FR-пункт из [requirements.md](requirements.md), к которому она относится.
- Понятен бизнес-контекст (какой критерий паспорта кейса закрывает).
- Определены входные данные и ожидаемый результат (для ML — JSON-схема; для бота — поведение FSM).
- Есть критерий приёмки, привязанный к `tests.json` или демонстрационному сценарию.
- Нет неразрешённых зависимостей (например, формат карточки согласован ML ↔ Fullstack).
- Есть оценка по времени в рамках 3-дневного окна.

---

## 2. Definition of Done (DoD) для функций
Функция считается завершённой, если:

- **Реализована в коде и доступна через интерфейс** (Telegram-бот или тестовый экран) либо через внутренний API ML-сервиса.
- **Протестирована по критериям приёмки:** корректный ввод → успешный сценарий; некорректный/пустой ввод → понятное сообщение без падения.
- **Данные сохраняются в SQLite** и соответствуют `output_example.json`.
- **Не нарушает запреты кейса:** нет обещаний дохода, выдуманных акций, лечебных свойств, реальных внешних действий; все сообщения наставнику — черновики.
- **Документация обновлена:** README (запуск/проверка), требования и таблицы проверок актуальны.
- **Проходит интеграционный прогон:** сквозной сценарий F002→F004→F006→вопрос об акции и `pytest` зелёные в Docker-сборке.

## 4. Критерии приёмки обязательного результата (по паспорту кейса)
1. Есть один интерфейс (чат/веб) и загрузка учебного события регистрации.
2. Уточняющие вопросы не запрашивают повторно уже известные сведения.
3. Карточка содержит `client_id`, цель, интересы, подтверждающую цитату, следующий шаг, флаг отказа.
4. Диалог останавливается по просьбе человека; при повторной загрузке события второй карточки нет.
5. Проверены все 12 ситуаций; для 10 содержательных совпадают сегмент, отказ и следующий шаг.
6. Нет обещаний дохода, выдуманных акций и внешней отправки.
7. Указаны версии зависимостей, внешние сервисы, стоимость запуска и ограничения.

## 5. Метрики успеха продукта
- 12/12 проверок `tests.json` пройдено.
- Сегментация на 10 примерах: 100%.
- Корректно извлечённые поля из свободных ответов: ≥ 90%.
- 0 запрещённых ответов (доход/акции/лекарства/внешние действия).
- Среднее время обработки сообщения ≤ 10 с (Ollama локально ≤ 30 с).
- Unit-покрытие ядра (извлечение, валидация, дедупликация) ≥ 70%.

## 6. North Star Metric
Доля первичных диалогов, завершённых заполненной карточкой с явной целью или явным отказом, которую наставник принял без доопроса клиента.

## 7. KPI по спринтам (3-дневное окно)

| Спринт | KPI готовности |
|--------|----------------|
| Спринт 0 (каркас) | Бот запускается, БД создаётся, LLM отвечает, репозиторий GitVerse доступен в инкогнито |
| Спринт 1 (обязательный сценарий) | F002 проходит целиком; промпт ≥300 строк готов; базовые unit-тесты зелёные |
| Спринт 2 (проверки) | ≥10/12 проверок `tests.json`; таблица результатов ведётся; Docker-сборка повторяема |
| Спринт 3 (сдача) | 12/12 или честная пометка; README/архитектура/видео готовы; ссылка и код команды переданы |
