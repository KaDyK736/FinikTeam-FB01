# Предложение по пилоту — ИИ-помощник нового клиента Faberlic (кейс FB01)

*Выжимка из плана-графика проекта (`UPRSII_LR_6.xls`, версия 1.0 от 24.09.2026). Репозиторий: https://github.com/KaDyK736/FinikTeam-FB01*

## Что предлагаем

Передать в пилотную эксплуатацию ИИ-агента первичного контакта: бот (aiogram 3, FSM-диалог) после события регистрации проводит первый диалог, LLM извлекает цель и интересы в карточку, наставник получает готовую карточку и черновик сообщения (автоотправка запрещена). Пилот подтверждает главную гипотезу — сокращение времени наставника на первичном контакте с ~40 мин до ~5 мин.

## Критерии успеха пилота (из паспорта проекта)

- ≥ 85% диалогов завершены карточкой, принятой наставником без доопроса;
- 12/12 проверок tests.json (уже есть частичное подтверждение: 10/10 базовых кейсов + 21/21 перефразов на локальной qwen2.5:7b — лог в репозитории);
- факт замера времени: ~40 мин → ~5 мин на контакт;
- 0 обещаний дохода, 0 выдуманных акций, 0 внешних автоотправок сообщений.

## Ключевые риски и как закрыты

| Риск (P×I) | Митигация |
|---|---|
| Нечёткость требований заказчика (0,72) | Интервью с держателем процесса, глоссарий, MVP-приоритет F002/F004/F006 |
| Недоступность внешних LLM (0,56) | Локальная Ollama как базовый контур + цепочка провайдеров с ретраями — **проверено на деле** |
| Некорректное извлечение полей (0,40) | Промпт с JSON-схемой и примерами, переспрос вместо догадки, регрессия на перефразах — **21/21 PASS** |
| Галлюцинации: обещания дохода/акций (0,36) | Детерминированные правила KB04/KB08, всё спорное — только черновик наставнику |

Условия остановки пилота: приёмка карточек держателем ниже 85% или единичный случай запрещённого обещания клиенту.

## Что нужно от заказчика для старта пилота

1. Выделенный представитель (владелец процесса — наставник) для приёмки;
2. Номера телефонов группы наставников для таблицы доступа;
3. Согласие на формат: сообщения клиентам — только черновики с ручным подтверждением;
4. Реальные (или приближённые) события регистрации вместо учебного потока — к моменту подключения интеграции с сайтом.
